# Architecture Context

- **Final email reviewer:** every customer send uses `hackloop.send_customer`, deterministic prose validation, one dedicated `email_review` pass with `LLM_REVIEW_MODEL=gpt-5`, and final validation before transport. The reviewer only edits style; numeric/currency/date/reference values, carrier names, signature and qualified statements are checked. Failures keep the checked draft. Costs are logged per RFQ; pause/manual/deadline controls are checked again after review. Machine carrier/trucker protocols retain `send`. Health exposes the active style, model and build.

- **Customer presentation:** `mail/style.py` provides written EN/DE month dates, safe standalone currency/date formatting and paragraph breaks at sentence boundaries. RFQ validation rejects parentheses, internal labels and unresolved display defects; deterministic customer templates use prose and the same date vocabulary. Technical IDs, filenames, contacts and stored API/CRM values remain intact.

- **Customer writing skill:** `.agents/skills/customer-email-voice/SKILL.md` combines Humanize Writing and Humanizer for this domain; pinned sources and MIT credits accompany it. `app/mail/voice.py` loads the shared `customer_voice.md` locally into the quote composer's system prompt, including repair attempts. No extra rewrite call or runtime download.
- **Writer tone:** the generating agent's shared profile uses a close, cheerful best-friend voice throughout the email. German defaults to du unless formal address is explicitly requested. Warmth applies on first contact without inventing shared history; factual contracts remain authoritative. The separate final reviewer's prompt, model, validation and send controls are unchanged.

- **Personal replies:** standard RFQs again use full extraction and the composer. Bounded current-thread and earlier same-customer correspondence informs tone and grounded references; older monetary amounts are removed from this context. Only verified current facts support price/service promises. Default gateway budget is eight calls for extraction, composition, repairs, rescue and final style reviews; templates are a failure fallback.

- **Mailbox ingress:** signed `/hooks/mailbox` persists into `mail_delivery` before acknowledging; workers and fallback polling share atomic claims and exact-ID deduplication. Pending/stored work resumes after restart; ambiguous dispatches become `unknown` with a warning for manual inspection. Only polling advances its cursor. Subscription and its private, persistent signing-secret file are managed explicitly with `python -m app.mail.webhook_admin`; never rotate on startup. See `DEPLOY.md`.

- **RFQ validation:** `app/mail/rfq_validation.py` checks the current request and attachment evidence before pricing. Drafts and clarification state live in `rfq_validation`; no session-table rebuild. Enforce is the default; explicit shadow mode remains available. Enforce uses same-thread customer evidence and handles clarification replies before booking.

- **Stack and conventions (binding):** [docs/TECH_SPEC.md](docs/TECH_SPEC.md): Python 3.11, FastAPI (built-in SSE), SQLite via `sqlite3` without ORM, threads instead of asyncio, one static HTML page with vanilla JS.
- **CRM, session model and sessions UI:** [docs/design/aufgabe-c.md](docs/design/aufgabe-c.md).
- **Session = one customer-started thread.** Mails are mapped to sessions via known mail IDs in `references`; every outgoing mail is stored with `db.record_outgoing()`.
- **Manual reply target:** UI/API default to the latest incoming customer mail, with explicit selection retained for carrier correspondence. Customer quotes are rejected for other recipients before takeover/send; only customer responses update `first_reply_at`. Confirmation and events name the recipient.
- **Booking price changes:** `app/agents/booking.py` confirms the customer only once the airline price is known (portal booking response, airline confirmation mail, or after `AIRLINE_CONFIRM_WAIT_S`=180). A deviation beyond `PRICE_CHANGE_TOLERANCE_PCT`=0.5 from the quoted air price asks the customer about the new all-in total and names one cheaper quote alternative; yes confirms, anything else is `needs_human`. No automatic rebooking (the portal has no cancel). State in `bookings.customer_state`.
- **History-first clarification:** the unified `rfq_validation` lifecycle searches same-thread customer evidence before asking, accumulates partial corrections and asks again for remaining gaps. Natural airport wording is resolved deterministically; unresolved RFQ replies get one evidence-bound full-thread pass with `LLM_RESCUE_MODEL` before human review. A durable reply ledger prevents duplicates; saved answers resume after restart. Booking/tracking questions share the lifecycle without treating questions as quotes or consent.
- **RFQ API costs:** `llm_calls.accounting_json` retains usage subtypes, frozen model rates and component estimates. Session detail exposes `llm_usage`; missing prices/usage are incomplete, legacy totals stay unchanged. Reasoning is included in output; cached input is discounted separately.
- **Boundaries:** only `app/hackloop.py` talks to the 5U API, only `app/llm.py` to the gateway, only `app/db.py` writes SQL. UI and agents are coupled only through the database (`events` table, `paused`/`mode` flags).
- **Pricing:** deterministic `app/pricing/`; Decimal amounts and integer cents. Tracked JSON files are seed data; runtime tariffs/portal snapshots live in `settings.runtime_dir` on the persistent volume. `portal_result()` adds structured 503 email fallbacks without changing `portal_options()`.
- **Portal outage bids:** RFQs reserve airline slots for eligible portal carriers before speculative email requests. On 503 these carriers take priority; healthy portal results release the reservation. Durable bid recipients count against the cap on restart; trucker slots remain independent.
- **Tariffs:** one durable SQLite queue and worker; text/table formats parsed locally, images/scanned PDFs transcribed through `llm.complete` with no pricing decisions. Sender and values validated before atomic publication and cache reload. Pending jobs resume on restart; failed jobs remain recorded with a warning.
- **FX/audit:** EUR/USD comparison with an explicit, expiring FX source. Customer output stays EUR. `RateOption` and `pricing_audit` events retain original currency, tariff version, ordinary/breakpoint totals, and the applied FX evidence.
- **RFQ reliability:** extraction retains explicit questions and constraints, with one schema-repair attempt. Customer attachments are untrusted evidence: supported files are parsed with bounded OCR fallback and material conflicts create one persisted clarification before pricing; clear replies resume, ambiguous or DG replies become manual. Pickup-zone routing wins over model output. The fact-bounded composer gets one validated repair before deterministic fallback. Carrier fan-out is capped, door-to-port quotes require trucking, and SQLite send/clarification claims keep retries idempotent.
- **Hosting:** one container on Railway (`Dockerfile`, `railway.json`, guide in `DEPLOY.md`), SQLite on a volume at `/data`, one replica only. UI behind HTTP Basic auth (`UI_USER`/`UI_PASSWORD`).
- **UI design:** tokens and components in `DESIGN.md` (v0.1, provisional); screens Live · CRM · Leistung.
